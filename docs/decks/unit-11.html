Abstraction of Programming

Multimedia and Application (BCA429CO)

Why abstraction?

  • Applications are procedural and hardware dependent
  • Changing a device → re-implementation
  • Abstraction levels: different detail for representing, accessing, manipulating data

Libraries and system software

  • Library: device functions; supplied with hardware; many, differing abstraction
  • System software: device access in the OS; RM / EDF schedulers
  • Nemo: supervisor call + system, device, application domains
  • Time capsule: LDU + data + life span · Stream: source → sink; MCI in Windows

Toolkits

  • Abstract from the physical layer
  • Uniform interface for all devices
  • Client-server paradigm · hide process structures
  • Same toolkit on all platforms: a wish (costs performance)

Language requirements

  • Parallel processes (compile time and dynamic)
  • IPC: understand time requirements, transmit and process on time
  • No new language: language extension
  • Examples: OCCAM-2, Ada

Multimedia class approaches

  • Application-specific and application-generic metaphors
  • Devices as classes (start, stop, seek)
  • Processing units: Lego-like data-flow path
  • Media class hierarchy · communication classes (information, presentation, transport)

BMO, SMO, CMO

  • SG:BMO: definite length · ST:BMO: undetermined duration
  • SMO = BMO + two headers
  • CMO = SMOs + orchestration header (time) + concatenation header (logic, space)
