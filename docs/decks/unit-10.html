Notion of Synchronization

Unit 10 · topic 1 of 5

Notion of SynchronizationIn plain words

The idea

Synchronization means the right media shown at the right time. It happens inside one stream (intra) and between streams (inter).

Real-life picture

Lip-sync: the speaker's lips must match the sound.

Remember it

Intra = smooth within a stream. Inter = aligned between streams. Live = real time source, synthetic = pre-planned.

Notion of SynchronizationIntroduction

  • The word synchronization refers to time.
  • In multimedia it means the temporal relation between media objects in the system: between time-dependent (continuous) objects and between time-dependent and time-independent (discrete) ones.
  • A common example is the synchronization of visual and acoustical information in television.

In short: coordinating several media types in time to give a seamless presentation, for example lip movement matching speech.

Notion of SynchronizationHard and soft synchronization

  • Hard sync: strict timing, for example a live news broadcast.
  • Soft sync: some delay is acceptable, for example offline playback.

Presentation RequirementsIn plain words

The idea

Humans accept small timing errors, but not large ones. Meeting these limits is a presentation requirement.

Real-life picture

If a speaker's voice is 200 ms behind the lips, viewers notice and get annoyed.

Remember it

Presentation RequirementsPresentation Requirements

For correct delivery at the user interface, synchronization is essential. A presentation requirement consists of:

  • for intra-object synchronization: the accuracy of delays in presenting the LDUs (logical data units);
  • for inter-object synchronization: the accuracy of the parallel presentation of media objects.
Source note: Presentation Requirements

Presentation RequirementsLip synchronization (1/2)

Lip synchronization is the temporal relation between an audio and a video stream when a person speaks.

  • The time difference between related audio and video LDUs is the skew.
  • Streams in perfect synchronization have skew = 0 ms.
  • Lip synchronization is tolerated within a skew of −80 ms (audio behind video) to +80 ms (audio ahead of video).
Source note: Presentation Requirements

Presentation RequirementsLip synchronization (2/2)

Source note: Presentation Requirements

Presentation RequirementsPointer synchronization

In a CSCW (computer-supported cooperative work) environment, cameras and microphones are attached to each user's workstation. A speaker uses a pointer to indicate elements of a graphic while talking, so audio and pointer must be synchronized. Experiments gave:

Case Tolerated skew
Audio ahead of pointing 750 ms
Pointing ahead of audio 500 ms

Reference Model

Reference ModelIn plain words

The idea

A reference model organises synchronization into layers so that each layer solves one problem: from raw media up to the author's specification.

Real-life picture

Like postal service layers: the truck (media), the sorting centre (stream), the parcel (object), the order form (specification).

Remember it

Four layers: media, stream, object, specification.

Say: A reference model organises synchronization into layers so that each layer solves one problem: from raw media up to the author's specification.

Board: write the memory hook: Four layers: media, stream, object, specification.

Timing: about 3 minutes; then continue to the detailed slides.

Reference ModelWhy a reference model?

Synchronization is needed at several points and by several kinds of users, from a device programmer to an author. A reference model divides the problem into layers, each giving a synchronization mechanism through an interface.

  • The interfaces can be used to specify or enforce temporal relations.
  • Each interface defines services, offering the user a way to state requirements.
  • Each layer can be used directly by an application or by the next higher layer to build its own interface.

It lets us compare existing systems, place each function where it belongs, and design new systems in a modular way.

Source note: Reference Model

Reference ModelThe four layers (1/2)

Source note: Reference Model

Reference ModelThe four layers (2/2)

Layer Operates on Abstraction offered Functions
Media layer One continuous media stream, a sequence of LDUs A device-independent interface with operations such as read and write Simple implementations, or ones that handle two interleaved streams
Stream layer Streams and groups of streams Continuous media as a data flow with implicit time constraints; individual LDUs are not visible Runs in a real-time environment; the application starts, stops and groups streams and defines QoS in timing parameters; inter-stream synchronization inside a group; the application synchronizes streams with time-independent media
Object layer All media types; hides the difference between discrete and continuous media The complete, synchronized presentation Takes a synchronization specification as input; computes and executes the presentation schedule including discrete objects and calls to the stream layer; closes the gap between the needs of a synchronized presentation and the stream services
Specification layer Tools An open layer with no explicit interface Synchronization editors, multimedia document editors, authoring systems; converts specifications to the object-layer format; maps user-level QoS to the qualities of the object-layer interface
Source note: Reference Model

Reference ModelAlternative naming (1/2)

Some courses name the layers Media (raw files such as .mp4, .mp3), Stream (streams and buffering, for example YouTube), Session (manages sessions, for example Netflix) and Sync (coordinates all media timing).

Which to write in the exam

The textbook version (media, stream, object, specification) is standard and the assignment questions ask for the "four-layer synchronization reference model". Write the textbook version and, if useful, add one line that some courses call the upper layers "session" and "sync".

Synchronization SpecificationIn plain words

The idea

A specification tells the system how media are related in time. Different methods describe this in different ways.

Real-life picture

A slide show script: 'show slide 2 when narration clip 1 ends'.

Remember it

Four common categories: interval-based, axes (timeline) based, control-flow based, event-based.

Synchronization SpecificationSynchronization Specification

A synchronization specification of a multimedia object describes all temporal dependencies of the objects it contains. It is produced with the tools of the specification layer and used at the interface to the object layer.

What it contains

  1. Intra-object synchronization specification for each media object.
  2. QoS description for intra-object synchronization.
  3. Inter-object synchronization specification.
  4. QoS description for inter-object synchronization.

QoS levels: QoS for one media object, for two related objects, and for several related objects.

Source note: Synchronization Specification

Synchronization SpecificationCategories of specification methods (1/3)

Category Idea
Interval-based Relates the time intervals of presentation of objects (for example before, meets, overlaps, during); durations for time-dependent and time-independent objects
Axes-based Relates presentation events to axes shared by the objects: a global timer or virtual axes
Control-flow based The presentation flow is synchronized at predefined points: basic hierarchical specification, reference points, time Petri nets
Event-based Presentation actions are started by synchronization events: start, stop, prepare presentation
Source note: Synchronization Specification

Synchronization SpecificationCategories of specification methods (2/3)

Scripts are a textual description of a synchronization scenario; they are powerful because they provide a full programming environment.

Source note: Synchronization Specification

Synchronization SpecificationCategories of specification methods (3/3)

Slide-deck techniques: timeline models (Gantt style), time-stamping (for example MP4 metadata) and script-based (for example SMIL); example: slide narration in an e-learning module.

Source note: Synchronization Specification

Synchronization SpecificationRequirements on a specification method (1/2)

  1. Support object consistency and maintenance of the specification.
  2. Give an abstraction of the content of a media object so temporal relations can be stated.
  3. Describe all types of synchronization relations easily.
  4. Integrate time-dependent and time-independent media.
  5. Support QoS requirements.
  6. Support hierarchical levels of synchronization.
Interval-based example

Slide 1 (10 s) is shown during the narration clip (10 s); slide 2 starts when slide 1 ends and the animation overlaps the last 5 s of slide 2. Each statement relates two intervals.

Source note: Synchronization Specification

Synchronization SpecificationRequirements on a specification method (2/2)

Extra

The thirteen interval relations of Allen's algebra (before, meets, overlaps, starts, during, finishes, equals and their inverses) underlie interval-based specification. Time Petri nets use places and transitions with durations. Learn the names above, not the formalism, unless your teacher asks.

Exam tip

"Briefly describe synchronization specification" = what it contains, the four method categories with one line each, and one or two of the six requirements.

Synchronization in a Distributed EnvironmentIn plain words

The idea

In a network the sender and receiver have different clocks and the delay varies, so synchronization needs buffering and clock agreement.

Real-life picture

Two friends watch a stream together; each device downloads at a different speed.

Remember it

Delay variation is removed by buffers; clock drift by clock sync.

Synchronization in a Distributed EnvironmentSynchronization in a Distributed Environment (1/5)

Synchronization is more complex in a distributed environment than in a local one, because the source, the network and the sink are separate and have separate clocks. The elements:

Source note: Synchronization in a Distributed Environment

Synchronization in a Distributed EnvironmentSynchronization in a Distributed Environment (2/5)

  1. Transport of the synchronization specification. Three approaches:
    1. deliver the complete synchronized information before the presentation starts;
    2. use an additional synchronization channel;
    3. use a multiplexed data stream (specification and media in one stream).
  2. Location of synchronization: synchronize media objects by combining them into a new media object, at the source or at the sink.
  3. Clock synchronization: the accuracy between the clocks of source and sink nodes must be considered.
  4. Multiple communication relations: communication patterns with several sinks need run-time handling.
Source note: Synchronization in a Distributed Environment

Synchronization in a Distributed EnvironmentSynchronization in a Distributed Environment (3/5)

  1. Multi-step synchronization: it must be maintained through all steps so that the sink can do the final synchronization:
    1. during object acquisition (digitizing a video frame);
    2. during retrieval (synchronized access to frames of stored video);
    3. during delivery of LDUs to the network;
    4. during transport;
    5. at the sink;
    6. within the output device.
Source note: Synchronization in a Distributed Environment

Why clocks matter

If the sender's clock runs 0.1 % fast relative to the receiver's, after 10 minutes (600 s) the receiver has accumulated 600 × 0.001 = 0.6 s of drift, far beyond the ±80 ms lip-sync limit. Clock synchronization or buffer adaptation is needed.
