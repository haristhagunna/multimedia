Introduction and Real Time

Unit 7 · topic 1 of 4

Introduction and Real TimeWhy an ordinary OS is not enough (1/2)

An operating system (OS) manages the hardware resources (CPU, memory, disk, network) and offers them to applications. Conventional OSs were designed for discrete data and fairness: they give each process a fair share, with no promise about when a result appears.

Multimedia needs more because continuous media (audio, video) have time constraints: each logical data unit (LDU, for example one video frame every 40 ms at 25 fps) must be processed and presented on time, or the user sees jerky video and hears clicks.

Source note: Introduction and Real Time

Introduction and Real TimeWhy an ordinary OS is not enough (2/2)

Requirements on a multimedia OS
  1. Real-time processing of continuous media (meet deadlines).
  2. Resource management with QoS guarantees (CPU, memory, bandwidth, buffers).
  3. Efficient data handling: large data volumes, continuous media file system, fast copying.
  4. Synchronisation support (audio and video together).
  5. Support for both discrete and continuous media at the same time.
  6. Low latency and small jitter, with predictable behaviour.
Source note: Introduction and Real Time

Introduction and Real TimeReal time (1/2)

A real-time process is a process that delivers its result within a given time span. A real-time system is a system that delivers results within given time limits. Correctness depends on both the value and the time of the result.

  • The time limit is the deadline.
  • A real-time system must be predictable: the worst-case behaviour must be known.
Hard real time Soft real time
Deadline miss Not allowed: failure may be catastrophic Tolerated occasionally; quality drops
Guarantee Deterministic, based on worst case Statistical or best effort
Examples Nuclear plant control, flight control, airbag Video and audio playback, video conferencing
In multimedia Rare (for example some medical or studio uses) Typical
Source note: Introduction and Real Time

Introduction and Real TimeReal time (2/2)

Deadlines in multimedia

A deadline is the latest time by which the work must finish. For a video at 25 fps, each frame's period is 1 ÷ 25 = 40 ms; the frame must be decoded and displayed within its period. For CD-quality audio in 1 ms blocks, the period is 1 ms.

Characteristics of real-time processing

  • Periodic (continuous media: one LDU every period P) or aperiodic (event driven, for example a mouse click).
  • Predictable and bounded execution time.
  • Latency (delay from request to result) and jitter (variation of the delay) must be small.
Source note: Introduction and Real Time

Introduction and Real TimeCheckpoint

Check yourself

Differentiate hard and soft real time with examples.

Hard: a missed deadline is a failure (flight control). Soft: occasional misses are tolerated (video playback).

Check yourself

Why does a general-purpose OS fail for video?

It gives fair sharing but no time guarantees, so frames may be late.

Resource Management

Unit 7 · topic 2 of 4

Resource ManagementResources

A resource is anything a process needs to run.

Kind Examples
Active (provide a service over time) CPU, network adapter, disk controller
Passive (provide capacity) Main memory, bandwidth of bus, network and disk, buffer space
Source note: Resource Management

Resource ManagementRequirements

For continuous media the resource manager must:

  1. Share resources among competing processes (and with discrete-media work).
  2. Guarantee the capacity each continuous media stream needs (deadlines, bandwidth, buffers).
  3. Handle several streams at once with different QoS.
  4. Reject a new request if it would break existing guarantees (admission control).
Source note: Resource Management

Resource ManagementAllocation schemes (1/2)

Resource allocation works with reservation of resources before use.

  1. The application states its QoS requirements (for example frame rate, delay).
  2. The system maps them into resource requirements.
  3. Admission control (schedulability test): can the request be served together with all existing guarantees?
  4. If yes, the resources are reserved (accepted); if no, the request is rejected or renegotiated with lower QoS.
  5. During the run the system enforces the reservation and monitors it.
Source note: Resource Management

Admission control by utilisation

Two audio and one video streams already use 70 % of the CPU. A new stream needs 40 %. 70 + 40 = 110 % > 100 %, so it is rejected (or offered a lower frame rate needing, say, 25 %).

Source note: Resource Management

Resource ManagementContinuous media resource model (LBAP) (1/2)

The model describes the workload a stream puts on a resource and the guarantee the system gives. The Linear Bounded Arrival Process (LBAP) characterises a stream by three parameters:

Symbol Meaning
M Maximum message (LDU) size
R Maximum message rate (messages per second)
B Maximum burst (number of messages that may arrive back to back)

The number of messages arriving in any interval of length t is bounded linearly:

164\text{messages in } t \;\le\; B + R\cdot t164

Source note: Resource Management

Resource ManagementContinuous media resource model (LBAP) (2/2)

Check

A video stream with R = 25 messages/s and burst B = 3: in 2 s at most 3 + 25 × 2 = 53 messages. If M = 10 KB per frame, the peak data rate is M × R = 250 KB/s.

Associated ideas in the model:

  • Each message needs processing time on the resource and has a deadline (delay bound).
  • A resource manager per resource performs the schedulability test and the reservation.
  • Buffers absorb the burst B and the jitter.
  • The end-to-end QoS is the combination of the guarantees of all resources along the path (disk, CPU, network).
Source note: Resource Management

Resource ManagementCheckpoint

Check yourself

To protect the guarantees already given: a new stream is accepted only if the resources remain sufficient for all.

Maximum message size, maximum message rate, maximum burst.

Process Management and Real-Time Scheduling

Unit 7 · topic 3 of 4

Process Management and Real-Time SchedulingReal-time processing requirement (1/2)

For continuous media the process manager must schedule processes so that every periodic task meets its deadline. A periodic task is described by:

Symbol Meaning
C Computation (execution) time per period
P Period (a new instance is released every P)
D Deadline, usually D = P (finish before the next instance)
U = C ÷ P Utilisation: the fraction of the CPU the task needs

Total utilisation of n tasks: U = Σ Cᵢ ÷ Pᵢ. If U > 1, no scheduler can succeed.

Source note: Process Management and Real-Time Scheduling

Process Management and Real-Time SchedulingReal-time processing requirement (2/2)

A video task

Decoding a frame takes C = 10 ms and frames come every P = 40 ms (25 fps): U = 10 ÷ 40 = 0.25 (25 % of the CPU).

Real-time scheduling

  • A conventional scheduler (round robin, priority, FIFO) ignores deadlines.
  • A real-time scheduler orders tasks by their timing. Two classical algorithms are used for continuous media: Earliest Deadline First and Rate Monotonic.
  • Both are preemptive: a higher-priority task can interrupt the running one.
  • Assumptions: periodic tasks, D = P, independent tasks, negligible switching time.
Source note: Process Management and Real-Time Scheduling

Process Management and Real-Time SchedulingEarliest Deadline First (EDF)

  • Rule: at every moment run the ready task whose absolute deadline is nearest.
  • Dynamic priority (priorities change as deadlines approach); optimal for a single CPU: if any algorithm can meet all deadlines, EDF can.
  • Schedulability test (D = P): the task set is schedulable if and only if U ≤ 1.
Source note: Process Management and Real-Time Scheduling

Process Management and Real-Time SchedulingRate Monotonic (RM)

  • Rule: assign static priorities by rate: the task with the shortest period (highest rate) gets the highest priority; run the highest-priority ready task.
  • Static priority, simple to implement, predictable; optimal among static-priority algorithms.
  • Sufficient test (Liu and Layland):

181U \le n\left(2^{1/n}-1\right)181

n 1 2 3 4 → ∞
Bound 1.000 0.828 0.780 0.757 0.693

If U is below the bound, RM surely works. If U is above it but ≤ 1, RM may or may not work (a timeline decides). EDF works up to U = 1.

Source note: Process Management and Real-Time Scheduling

Tasks: T1 (C = 1, P = 4) and T2 (C = 2, P = 6). U = 1/4 + 2/6 = 0.25 + 0.333 = 0.583. RM bound for n = 2 is 0.828, so RM is guaranteed.

System Architecture

System ArchitectureGoal

Provide, on top of the hardware, a real-time environment that serves continuous media with guaranteed QoS together with ordinary applications.

Source note: System Architecture

System ArchitectureLayers

Source note: System Architecture

System ArchitectureComponents

Component Role
Real-time scheduler EDF or rate monotonic scheduling of continuous media processes
Resource managers and QoS manager Admission control, reservation, monitoring (see Resource Management)
Memory management Pinned (non-swappable) buffers, avoid page faults, avoid copying (shared buffers)
Continuous media file system Placement and disk scheduling (for example EDF or SCAN-EDF) for steady rates; large files; multiple streams
IPC Timely transfer of continuous data between processes
Device drivers Hide audio/video hardware, with time-bounded interrupt handling
Network subsystem Real-time transport (see Unit 8)
Source note: System Architecture

System ArchitectureArchitectural approaches

Approach Idea Comment
Extend a conventional OS Add real-time classes, QoS and a continuous media file system to Unix or Windows Practical; incomplete guarantees
Real-time micro-kernel Small kernel offers scheduling, memory, IPC; services run as user-level servers Predictable and flexible
Dedicated multimedia OS Built around QoS and resources from the start (the Nemo idea in Unit 11) Best guarantees, little software
Design rules

Keep kernel paths short and bounded, avoid copying data between layers, make resource accounting explicit, and let applications adapt when the system cannot give full QoS.

Source note: System Architecture

System ArchitectureCheckpoint

Check yourself

Why does a multimedia OS pin memory and avoid copying?

Page faults and copies add unbounded delay and CPU load; pinned shared buffers give predictable timing.

Check yourself

Name the two main ways of building a multimedia OS.

Extend a conventional OS with real-time features, or build on a real-time micro-kernel.
