Multimedia Documents

Unit 9 · topic 1 of 4

Multimedia DocumentsIn plain words

The idea

A multimedia document is more than data: it has content, a logical structure (chapters, sections) and a layout (how it is shown).

Real-life picture

A web page: the text is the content, headings define the structure and CSS defines the layout.

Remember it

Content, structure, layout: keep them separate for flexibility.

Multimedia DocumentsWhat is a document?

A document is a structured collection of information intended for presentation to a reader. A multimedia document combines discrete media (text, graphics, images) and continuous media (audio, video, animation) with temporal, spatial and logical relations among them.

Source note: Multimedia Documents

Multimedia DocumentsDocument architecture

A document architecture defines how the document is structured and represented so that it can be created, edited, exchanged and presented on different systems. It separates three things:

Structure Describes
Logical structure The meaning-based organisation: chapters, sections, paragraphs, figures, captions
Layout structure The presentation: pages, columns, fonts, positions on the output device
Content The data itself: character text, raster or geometric graphics, audio, video

A multimedia architecture adds the temporal structure (when each object is presented) and hyperlinks (see Hypertext).

Source note: Multimedia Documents

Document architectureForms of a document

  • Formatted form: ready to present; cannot be edited easily (like a printout).
  • Processable form: carries the logical structure, so it can be edited and reformatted.
  • Formatted processable form: both.
Source note: Multimedia Documents

Multimedia DocumentsManipulation of multimedia data (1/2)

Operations on multimedia documents:

  1. Creation and capture of media objects (scanning, recording).
  2. Editing: cut, copy, paste, rearrange; edit the structure.
  3. Integration: combine media (authoring tools); specify layout, time and interaction.
  4. Storage and retrieval: databases, indexing and search of text, image, audio and video.
  5. Transformation and conversion: change format and resolution; compress.
  6. Presentation and interchange: formatting, play-out, and transfer between systems using a standard (SGML, ODA, MHEG).
Source note: Multimedia Documents

Multimedia DocumentsManipulation of multimedia data (2/2)

Exam tip

"Why are document architectures needed?" Answer: interchange between different systems and editors, separate logical content from layout, reuse, and consistent presentation.

Source note: Multimedia Documents

Hypertext and Hypermedia

Unit 9 · topic 2 of 4

Hypertext and HypermediaIn plain words

The idea

Hypertext connects pieces of information with links, and the reader chooses the path. Hypermedia does the same with all media.

Real-life picture

Wikipedia: every blue word leads to another article.

Remember it

Hypertext = nodes + links + anchors. The Dexter model describes the layers.

Hypertext and HypermediaHypertext

Hypertext is text organised as a network of linked nodes that the reader can follow in a non-linear order, in contrast with ordinary text that is read from start to end.

  • Idea: Vannevar Bush's Memex (1945), a machine to link and follow associative trails.
  • The word hypertext was coined by Ted Nelson (1965). Xanadu was his project; HyperCard (1987) and the World Wide Web (1989–91, Berners-Lee) made it popular.

Hypermedia

Hypermedia extends hypertext so that the nodes may contain any media (graphics, audio, video), not only text.

Source note: Hypertext and Hypermedia

Hypertext and HypermediaMultimedia (1/2)

Multimedia is the integrated presentation of several media; it does not by itself require non-linear navigation.

Multimedia Hypertext Hypermedia
Media Several Text only Several
Structure Often linear or time based Linked network Linked network
Navigation May be sequential Non-linear, by links Non-linear, by links
Example A film, a slide show A help system of text pages The Web with images and video
Source note: Hypertext and Hypermedia

Hypertext and HypermediaMultimedia (2/2)

Hypermedia = hypertext + multimedia

Hypermedia is the union: the links of hypertext with the media of multimedia.

Source note: Hypertext and Hypermedia

Hypertext and HypermediaAdvantages and problems

  • Advantages: flexible access, associative browsing, user control, rich presentation.
  • Problems: disorientation ("lost in hyperspace"), cognitive overhead (too many choices), difficulty keeping a sense of the whole.
  • Remedies: overview maps, history and back button, bookmarks, guided tours, clear link labels.
Source note: Hypertext and Hypermedia

Hypermedia Systems

Unit 9 · topic 3 of 4

Hypermedia SystemsIn plain words

The idea

Hypermedia systems grew from an early idea in 1945 to the World Wide Web, which made linked multimedia available to everyone.

Real-life picture

From Vannevar Bush's imagined Memex to the browser you use today.

Remember it

Remember the line: Memex (1945), hypertext term (1965), Web (1989 to 1991).

Hypermedia SystemsNodes

A node (also card, page, frame) is a unit of information: text, image, audio, video, or a composite node containing other nodes. Good practice: one node per single idea, so it can be linked in several contexts.

Source note: Hypermedia Systems

Hypermedia SystemsLinks (pointers)

A link connects a source to a destination. The anchor is the active part inside a node (a word, a region of a picture, a time range of a video).

Property Options
Direction Unidirectional or bidirectional
Cardinality One-to-one, one-to-many, many-to-many
Storage Embedded in the node (as in HTML) or external (kept in a separate link base)
Type Navigational, reference, annotation, structural (part-of), temporal (for time-based media)
Activation By the reader (click), automatic, or by time

A link may also be to a point or a range in the destination, and may trigger an action (play a clip).

Source note: Hypermedia Systems

Hypermedia SystemsArchitecture: the Dexter hypertext reference model (1/2)

The Dexter model describes hypertext systems in three layers:

Source note: Hypermedia Systems

Hypermedia SystemsArchitecture: the Dexter hypertext reference model (2/2)

Layer Role
Run-time layer How the hypertext is presented and how users interact
Storage layer The database of nodes (components) and links with their identifiers and anchoring
Within-component layer The content and internal structure of each node, outside the model

Interfaces: presentation specifications (between run-time and storage) and anchoring (between storage and within-component).

Source note: Hypermedia Systems

Hypermedia SystemsA typical hypermedia system

A hypermedia system has an authoring part (create nodes and links), a database (nodes, link base, indexes), a browser/navigation part (follow links, maps, history, search) and, for multimedia, a presentation engine for time-based media. Examples: HyperCard, early CD-ROM encyclopedias, the World Wide Web.

Exam tip

Source note: Hypermedia Systems

SGML, ODA and MHEG

Unit 9 · topic 4 of 4

SGML, ODA and MHEGIn plain words

The idea

Three standards describe documents and objects: SGML separates content from formatting, ODA exchanges office documents and MHEG describes multimedia objects for interchange.

Real-life picture

HTML grew from SGML ideas: tags describe the meaning of parts, a style sheet decides the look.

Remember it

SGML = markup with a DTD. ODA = logical + layout structure. MHEG = multimedia objects for exchange.

SGML, ODA and MHEGLogical structure of a document

SGML, ODA and MHEGSGML: Standard Generalized Markup Language (ISO 8879, 1986) (1/2)

  • A meta-language for defining markup languages. The document is text with tags that mark its logical structure; layout is not specified (left to the application).
  • Parts of an SGML system:
  • Document Type Definition (DTD): declares the allowed elements, their order and nesting and attributes.
  • The document instance: the marked-up content.
  • Entities: named pieces of text or data.
  • HTML is an SGML application; XML is a simplified subset.
<!ELEMENT book (title, chapter+)>
<!ELEMENT chapter (heading, paragraph*)>
<!ELEMENT title (#PCDATA)>

<book>
  <title>Multimedia</title>
  <chapter><heading>Audio</heading><paragraph>Sound is ...</paragraph></chapter>
</book>
Source note: SGML, ODA and MHEG

SGML, ODA and MHEGSGML: Standard Generalized Markup Language (ISO 8879, 1986) (2/2)

  • Advantages: platform independent, long-lived, validated by the DTD, reusable. Limits: no layout, no time or multimedia synchronisation (hence HyTime, an SGML-based standard for hypermedia and time).

ODA: Open Document Architecture (ISO 8613)

  • An architecture for interchange of documents between systems of different vendors, covering structure, content and layout.
  • Two structures per document:
Structure Contains
Logical structure Chapters, sections, paragraphs (the author's view)
Layout structure Pages, blocks, frames (the reader's view)
Source note: SGML, ODA and MHEG

SGML, ODA and MHEGODA: Open Document Architecture (ISO 8613) (2/2)

  • A document profile holds attributes of the document as a whole.
  • Content architectures: character content, raster graphics and geometric graphics. (Later extensions added audio and video.)
  • Forms: formatted (FF), processable (PF), formatted processable (FPF).
  • Interchange formats: ODIF (data stream) and ODL (language).
  • Compared with SGML: ODA includes layout as well as logical structure.
Source note: SGML, ODA and MHEG

SGML, ODA and MHEGMHEG: Multimedia and Hypermedia information coding Experts Group (ISO/IEC 13522) (1/3)

  • A standard for the coding of multimedia and hypermedia information objects for interchange between applications and systems, especially interactive TV and set-top boxes (final-form, run-time use).
  • Object-oriented: a document is a set of MHEG objects that a receiver (the MHEG engine) interprets and presents. It is not an authoring or editing format: it is the final form.
  • Main classes of objects:
Source note: SGML, ODA and MHEG

SGML, ODA and MHEGMHEG: Multimedia and Hypermedia information coding Experts Group (ISO/IEC 13522) (2/3)

Class Role
Content Wraps the media data (text, graphic, audio, video) and its coding
Selection / Modification / Interaction Offer user choices and interaction
Composite Groups other objects into a presentation or scene
Action Operations on objects (start, stop, set volume)
Link Condition → action: when an event happens, do the actions
Script Embeds a program for complex behaviour
Descriptor Describes the resources an object needs, for negotiation
Container A package of objects for interchange
Macro Reusable definitions
Source note: SGML, ODA and MHEG

SGML, ODA and MHEGMHEG: Multimedia and Hypermedia information coding Experts Group (ISO/IEC 13522) (3/3)

  • MHEG supports time-based presentation, spatial layout, links and interaction, so it covers what SGML and ODA do not (synchronised multimedia).
  • MHEG-5 (a simplified, widely used version) is used for digital TV in several countries.
SGML ODA MHEG
Describes Logical structure by markup Logical + layout of documents Final-form multimedia objects
Time and media No Limited Yes (synchronised)
Typical use Publishing, HTML/XML Office document interchange Interactive TV, multimedia interchange
