<section class="cheat"><h2>Unit 1: Multimedia System</h2>
<div class="cheat-f"><b>Formulas and facts</b><ul><li>Multimedia = Computer-controlled + Integrated + Digital + Interactive (CIDI)</li><li>Discrete: text, image, graphics. Continuous: audio, video, animation.</li></ul></div>
<div class="cheat-hooks"><b>Memory hooks</b><ul><li>A true multimedia system is Computer-controlled, Integrated, Digital and Interactive: remember it as the word CIDI.</li><li>Five jobs to remember: generate, represent, store, transmit, search and retrieve; compression and processing sit across all of them.</li><li>Three domains and one bar: Application, System, Device, with Synchronization running through all three.</li><li>Six categories: Perception, Representation, Presentation, Storage, Transmission, Exchange. Memory sentence: Please Read Pages, Study Thoroughly Every day.</li><li>Discrete = space only. Continuous = space + time. Three properties: combination, independence, computer-supported integration.</li><li>Asynchronous = whenever. Synchronous = not later than a limit. Isochronous = not earlier and not later: a steady rhythm.</li></ul></div>
<div class="cheat-terms"><b>Key terms</b><dl><dt>Medium</dt><dd>A means of distributing and presenting information (text, graphics, speech, music, video).</dd><dt>Multimedia</dt><dd>Computer-controlled integration of several media, represented digitally and usually interactive.</dd><dt>Discrete medium</dt><dd>Time-independent: text, still images, graphics.</dd><dt>Continuous medium</dt><dd>Time-dependent: audio, video, animation.</dd><dt>Hypertext</dt><dd>Text organised as linked nodes that the reader can follow in any order.</dd><dt>Non-linear</dt><dd>The user, not the author, chooses the path through the content.</dd><dt>Multimedia system</dt><dd>A system that processes multimedia data and applications.</dd><dt>Hardware</dt><dd>Capture, storage, processing and presentation devices.</dd><dt>Software</dt><dd>Operating system, drivers and application programs.</dd><dt>Network</dt><dd>Carries media between systems, usually with real-time needs.</dd><dt>Compression</dt><dd>Reducing the amount of data needed to represent a medium.</dd><dt>Application domain</dt><dd>Tools and applications that users work with; provides the user interface.</dd><dt>System domain</dt><dd>Database systems, operating system and communication services.</dd><dt>Device domain</dt><dd>Physical devices: capture, storage, input and output hardware.</dd><dt>Synchronization</dt><dd>Keeps media in the right time relation across all domains.</dd><dt>Perception medium</dt><dd>How humans sense information: seeing and hearing.</dd></dl></div>

<section class="cheat"><h2>Unit 2: Sound and Audio</h2>
<div class="cheat-f"><b>Formulas and facts</b><ul><li>Nyquist: fs ≥ 2·fmax</li><li>Size (bytes) = rate × bits/8 × channels × seconds</li><li>CD-DA = 44,100 × 16 × 2 = 1,411,200 bit/s</li><li>Levels = 2^bits</li></ul></div>
<div class="cheat-hooks"><b>Memory hooks</b><ul><li>Amplitude decides loudness, frequency decides pitch. Humans hear about 20 Hz to 20 kHz. Frequency f = 1 / T.</li><li>Sample at least twice the highest frequency (Nyquist). Size = rate × (bits/8) × channels × seconds.</li><li>MIDI files are tiny and easy to edit, but they need a synthesizer to be heard. Note On = status byte + key number + velocity.</li><li>Who = verification and identification. What = recognition and understanding. How = emotion and state of the speaker.</li><li>Two steps of synthesis: text is transcribed into a sound script, then the sounds are synthesised into speech.</li><li>PCM = accurate but big. Source encoding = smaller. Recognise-then-synthesise = smallest, but the original voice is lost.</li></ul></div>
<div class="cheat-terms"><b>Key terms</b><dl><dt>Sound</dt><dd>Mechanical wave energy that travels through a medium.</dd><dt>Audio</dt><dd>Electrical signal (analog or digital) that represents sound.</dd><dt>Amplitude</dt><dd>Height of the wave: loudness.</dd><dt>Frequency</dt><dd>Cycles per second (Hz): pitch.</dd><dt>Period T</dt><dd>Time of one full cycle; T = 1/f.</dd><dt>Infrasound / ultrasound</dt><dd>Below 20 Hz / above 20 kHz: not heard by humans.</dd><dt>Sampling rate</dt><dd>Number of samples per second, in Hz.</dd><dt>Bit depth</dt><dd>Bits per sample; 16 bits gives 65,536 levels.</dd><dt>Quantization</dt><dd>Rounding a sample to the nearest allowed level.</dd><dt>PCM</dt><dd>Pulse Code Modulation: samples written as binary codes.</dd><dt>Nyquist theorem</dt><dd>fs must be at least 2 × fmax to avoid aliasing.</dd><dt>Channel</dt><dd>Mono = 1 channel, stereo = 2.</dd><dt>MIDI</dt><dd>Musical Instrument Digital Interface: hardware and message standard (early 1980s).</dd><dt>Note On / Note Off</dt><dd>Messages that start and stop a note.</dd><dt>Velocity</dt><dd>How hard a key is struck (0 to 127).</dd><dt>Synthesizer</dt><dd>Device or software that makes sound from MIDI messages.</dd></dl></div>

<section class="cheat"><h2>Unit 3: Image and Graphics</h2>
<div class="cheat-f"><b>Formulas and facts</b><ul><li>Bitmap bytes = W × H × bits / 8</li><li>640×480×8-bit = 307,200 bytes</li><li>Dithering trades resolution for apparent colour depth</li></ul></div>
<div class="cheat-hooks"><b>Memory hooks</b><ul><li>Bitmap size = width × height × bits per pixel ÷ 8. Bitmaps store pixels; vector graphics store shapes.</li><li>Photos use JPEG. Sharp-edged graphics use PNG or GIF. TIFF is for high-quality storage.</li><li>Recognition pipeline: capture, pre-process, find features, label, interpret.</li><li>Transmission time = size in bits ÷ link rate. A 640 × 480 8-bit image is 307,200 bytes: about 38.4 s at 64 kbit/s.</li><li>Flow: host sends display commands, display controller draws into the refresh buffer, video controller reads the buffer and drives the monitor.</li></ul></div>
<div class="cheat-terms"><b>Key terms</b><dl><dt>Pixel</dt><dd>Picture element: the smallest unit of an image.</dd><dt>Resolution</dt><dd>Number of pixels, for example 640 × 480.</dd><dt>Bit depth</dt><dd>Bits per pixel: 1 = black/white, 8 = 256 values, 24 = true colour.</dd><dt>Bitmap</dt><dd>Image stored pixel by pixel.</dd><dt>Vector graphic</dt><dd>Picture stored as shapes and formulas.</dd><dt>RGB / CMY</dt><dd>Additive screen colours / subtractive print colours.</dd><dt>BMP</dt><dd>Simple, usually uncompressed bitmap.</dd><dt>GIF</dt><dd>Up to 256 colours, lossless, supports animation.</dd><dt>JPEG</dt><dd>Lossy compression suited to photographs.</dd><dt>PNG</dt><dd>Lossless compression with true colour and transparency.</dd><dt>TIFF</dt><dd>Flexible, high-quality format used in publishing and scanning.</dd><dt>Lossless vs lossy</dt><dd>Exact copy after decoding / some information lost.</dd><dt>Image analysis</dt><dd>Extracting information from images.</dd><dt>Image recognition</dt><dd>Deciding what the image or an object in it is.</dd><dt>Pre-processing</dt><dd>Cleaning the image: noise removal, contrast.</dd><dt>Segmentation</dt><dd>Splitting the image into regions or objects.</dd></dl></div>

<section class="cheat"><h2>Unit 4: Video and Animation</h2>
<div class="cheat-f"><b>Formulas and facts</b><ul><li>Y = 0.30R + 0.59G + 0.11B; U ∝ (B−Y); V ∝ (R−Y)</li><li>25 fps → 40 ms per frame</li><li>Raw 640×480×24-bit×25 fps = 184.32 Mbit/s</li></ul></div>
<div class="cheat-hooks"><b>Memory hooks</b><ul><li>25 frames per second means 40 ms per frame. PAL: 625 lines, 25 fps. NTSC: 525 lines, about 30 fps.</li><li>Data rate = width × height × bytes per pixel × frames per second. CIF is 352 × 288.</li><li>Y = 0.30R + 0.59G + 0.11B. The eye is more sensitive to brightness than to colour, so colour can use less bandwidth.</li><li>Key frames define the motion, in-betweens (tweening) fill the gaps. Film uses about 24 frames per second.</li><li>Describe the motion, not the pictures: this saves effort and data.</li><li>Double buffering: draw the next frame off-screen, then swap. Symbolic transmission is smaller than pixel transmission.</li></ul></div>
<div class="cheat-terms"><b>Key terms</b><dl><dt>Frame</dt><dd>One complete still image of a video.</dd><dt>Frame rate</dt><dd>Frames shown per second.</dd><dt>Interlacing</dt><dd>Sending odd lines then even lines (two fields) to reduce flicker.</dd><dt>Luminance (Y)</dt><dd>Brightness part of the signal.</dd><dt>Chrominance</dt><dd>Colour information.</dd><dt>Aspect ratio</dt><dd>Width to height, for example 4:3 or 16:9.</dd><dt>Digitizer</dt><dd>Converts analog video into digital frames.</dd><dt>Resolution</dt><dd>Pixels per frame.</dd><dt>Chroma subsampling</dt><dd>Storing colour at lower resolution than brightness.</dd><dt>CIF</dt><dd>Common Intermediate Format: 352 × 288 pixels.</dd><dt>RGB</dt><dd>Three separate colour signals.</dd><dt>YUV</dt><dd>Luminance plus two colour-difference signals (PAL).</dd><dt>YIQ</dt><dd>Luminance plus in-phase and quadrature signals (NTSC).</dd><dt>Composite</dt><dd>All components combined in one signal.</dd><dt>Digitization</dt><dd>Sampling and quantizing the video signal.</dd><dt>Key frame</dt><dd>A frame that defines an important pose or position.</dd></dl></div>

<section class="cheat"><h2>Unit 5: Data Compression</h2>
<div class="cheat-f"><b>Formulas and facts</b><ul><li>Ratio = original : compressed</li><li>Avg length = Σ pᵢ·lᵢ</li><li>RLE: aaabccdddd → a3b1c2d4</li><li>JPEG: 8×8 → DCT → quantize (lossy) → zigzag → RLE/Huffman</li></ul></div>
<div class="cheat-hooks"><b>Memory hooks</b><ul><li>Compression ratio = original size ÷ compressed size. Dialogue applications need a delay below about 150 ms.</li><li>Entropy = ignores meaning. Source = uses meaning. Hybrid = both.</li><li>Huffman: repeatedly merge the two smallest frequencies; left edge 0, right edge 1; no code is a prefix of another.</li><li>Send the difference, not the value: small numbers need fewer bits.</li><li>Pipeline: colour transform, 8 × 8 blocks, DCT, quantization, zig-zag, run-length / differential, Huffman.</li><li>I frames stand alone, P frames are predicted from the past, B frames from the past and the future.</li></ul></div>
<div class="cheat-terms"><b>Key terms</b><dl><dt>Redundancy</dt><dd>Repeated or predictable information that can be removed.</dd><dt>Lossless</dt><dd>Original is recovered exactly.</dd><dt>Lossy</dt><dd>Some information is permanently lost.</dd><dt>Compression ratio</dt><dd>Original size : compressed size.</dd><dt>Codec</dt><dd>Coder and decoder pair.</dd><dt>Symmetric coding</dt><dd>Encoding and decoding take similar effort.</dd><dt>Entropy coding</dt><dd>Lossless; treats data as a bit sequence: RLE, Huffman, arithmetic.</dd><dt>Source coding</dt><dd>Uses properties of the medium: prediction, transform, subband.</dd><dt>Hybrid coding</dt><dd>Combines techniques: JPEG, MPEG, H.261, DVI.</dd><dt>Run-length coding</dt><dd>Replaces runs with value and count.</dd><dt>DCT</dt><dd>Discrete Cosine Transform used in JPEG and MPEG.</dd><dt>Run</dt><dd>Consecutive repeats of the same value.</dd><dt>Prefix code</dt><dd>No code word is the start of another, so decoding is unambiguous.</dd><dt>Variable-length code</dt><dd>Code words of different lengths.</dd><dt>Priority queue</dt><dd>List kept sorted by frequency to find the two smallest.</dd><dt>Frequency</dt><dd>How often a symbol occurs.</dd></dl></div>

<section class="cheat"><h2>Unit 6: Optical Storage Media</h2>
<div class="cheat-f"><b>Formulas and facts</b><ul><li>Block = 2,352 bytes, 75 blocks/s</li><li>74 min × 60 × 75 = 333,000 blocks</li><li>Mode 1 user data 2,048 B (≈650 MB); Mode 2 2,336 B</li><li>Lasers: CD 780 nm, DVD 650 nm, Blu-ray 405 nm</li></ul></div>
<div class="cheat-hooks"><b>Memory hooks</b><ul><li>Three layers: polycarbonate substrate, reflective layer, protective layer. A change between pit and land represents a 1.</li><li>Shorter wavelength + smaller pits + tighter tracks = more capacity: CD 780 nm, DVD 650/635 nm, Blu-ray 405 nm.</li><li>Red Book. 44,100 × 16 × 2 = 1,411,200 bit/s. 74 min = 333,000 blocks of 2,352 bytes.</li><li>Yellow Book. Mode 1 = 2,048 user bytes + EDC/ECC. Mode 2 = 2,336 user bytes.</li><li>Photo CD resolutions: Base/16, Base/4, Base, 4 Base, 16 Base. CD-I = Green Book.</li><li>Orange Book covers both: WO = write once, MO = magneto-optical rewritable.</li></ul></div>
<div class="cheat-terms"><b>Key terms</b><dl><dt>Pit / land</dt><dd>Recessed / flat areas of the track.</dd><dt>Spiral track</dt><dd>One track winding from inside to outside.</dd><dt>Laser</dt><dd>Light source used to read (and write) the disc.</dd><dt>Substrate</dt><dd>Clear polycarbonate plastic carrying the pits.</dd><dt>CLV</dt><dd>Constant Linear Velocity: the disc speed varies so data passes at a constant rate.</dd><dt>Optical storage</dt><dd>Storage read with light.</dd><dt>LaserDisc</dt><dd>Analog video disc using laser reading.</dd><dt>DVD</dt><dd>Digital Versatile Disc: 4.7 GB single layer.</dd><dt>Blu-ray</dt><dd>Uses a blue-violet 405 nm laser; 25 GB per layer.</dd><dt>Track pitch</dt><dd>Distance between tracks: 1.6 µm CD, 0.74 µm DVD.</dd><dt>Dual layer</dt><dd>Two data layers read at different focus.</dd><dt>Red Book</dt><dd>Specification of the audio CD.</dd><dt>EFM</dt><dd>Eight-to-Fourteen Modulation: line code for the disc.</dd><dt>CIRC</dt><dd>Cross-Interleaved Reed-Solomon Code for error correction.</dd><dt>Subcode</dt><dd>Extra channel with track and time information.</dd><dt>Block / sector</dt><dd>2,352 bytes; 75 per second.</dd></dl></div>

<section class="cheat"><h2>Unit 7: Multimedia Operating System</h2>
<div class="cheat-f"><b>Formulas and facts</b><ul><li>U = Σ Cᵢ/Pᵢ</li><li>EDF: schedulable iff U ≤ 1 (D = P)</li><li>RM bound: n(2^(1/n) − 1); sufficient, not necessary</li><li>Example (2,5)+(4,7): U = 0.971 → EDF yes, RM no</li></ul></div>
<div class="cheat-hooks"><b>Memory hooks</b><ul><li>Hard real time: a missed deadline is a failure. Soft real time: a miss reduces quality.</li><li>Reserve first, then guarantee. LBAP model: B + R·t, the data that may arrive by time t.</li><li>Utilisation U = Σ C/P. EDF works if U ≤ 1. RM is guaranteed if U ≤ n(2^(1/n) − 1).</li><li>Goal: guarantee timing. Layers: device, driver, kernel scheduler, file system, application interface.</li></ul></div>
<div class="cheat-terms"><b>Key terms</b><dl><dt>Deadline</dt><dd>Latest time by which a task must finish.</dd><dt>Hard real time</dt><dd>Missing a deadline is unacceptable.</dd><dt>Soft real time</dt><dd>Occasional misses degrade quality only.</dd><dt>Periodic task</dt><dd>Task that repeats with a fixed period.</dd><dt>Jitter</dt><dd>Variation in timing.</dd><dt>Resource</dt><dd>Anything a stream needs: CPU, memory, bandwidth, disk.</dd><dt>Admission control</dt><dd>Accepting or rejecting a new request.</dd><dt>Reservation</dt><dd>Setting resources aside in advance.</dd><dt>LBAP</dt><dd>Linear Bounded Arrival Process model.</dd><dt>Utilisation</dt><dd>Fraction of a resource in use.</dd><dt>Period P</dt><dd>Time between releases of a periodic task.</dd><dt>Computation time C</dt><dd>CPU time needed per period.</dd><dt>Utilisation U</dt><dd>Sum of C/P over all tasks.</dd><dt>EDF</dt><dd>Earliest Deadline First: dynamic priority, optimal.</dd><dt>RM</dt><dd>Rate Monotonic: static priority by period.</dd><dt>Preemption</dt><dd>Interrupting a running task for a more urgent one.</dd></dl></div>

<section class="cheat"><h2>Unit 8: Multimedia Communication</h2>
<div class="cheat-f"><b>Formulas and facts</b><ul><li>Leaky bucket: constant output rate, overflow dropped</li><li>RTP: sequence no. + timestamp; RTCP: feedback</li><li>QoS: negotiate → admit → guarantee</li></ul></div>
<div class="cheat-hooks"><b>Memory hooks</b><ul><li>Needs: throughput, low delay, low jitter, tolerable loss, multicast.</li><li>QoS parameters: throughput, delay, jitter, loss. Shaping uses a leaky or token bucket.</li><li>UDP + RTP for media, RTCP for feedback, TCP is a poor fit for real time.</li><li>Collaborative computing + session management + architecture + mail and messaging.</li></ul></div>
<div class="cheat-terms"><b>Key terms</b><dl><dt>Bandwidth</dt><dd>Data capacity of a link.</dd><dt>Delay (latency)</dt><dd>Time for data to travel from sender to receiver.</dd><dt>Jitter</dt><dd>Variation of delay.</dd><dt>Loss</dt><dd>Fraction of data that does not arrive.</dd><dt>Multicast</dt><dd>One sender, many receivers.</dd><dt>QoS</dt><dd>Quality of Service guarantees.</dd><dt>Guaranteed / best effort</dt><dd>Firm promise / no promise.</dd><dt>Negotiation</dt><dd>Agreeing a QoS between user and system.</dd><dt>Token bucket</dt><dd>Allows bursts up to b and rate r.</dd><dt>Traffic shaping</dt><dd>Smoothing the flow to match the agreed profile.</dd><dt>RTP</dt><dd>Real-time Transport Protocol.</dd><dt>RTCP</dt><dd>RTP Control Protocol: quality reports.</dd><dt>UDP</dt><dd>Fast, connectionless transport without retransmission.</dd><dt>Sequence number</dt><dd>Detects loss and reordering.</dd><dt>Timestamp</dt><dd>Tells the receiver when to play a packet.</dd><dt>Collaborative computing</dt><dd>Several users working together using computers.</dd></dl></div>

<section class="cheat"><h2>Unit 9: Documents, Hypertext and MHEG</h2>
<div class="cheat-f"><b>Formulas and facts</b><ul><li>Hypermedia = hypertext + multimedia</li><li>Dexter layers: Run-time / Storage / Within-component</li><li>SGML: structure via DTD; ODA: logical + layout; MHEG: final-form objects</li></ul></div>
<div class="cheat-hooks"><b>Memory hooks</b><ul><li>Content, structure, layout: keep them separate for flexibility.</li><li>Hypertext = nodes + links + anchors. The Dexter model describes the layers.</li><li>Remember the line: Memex (1945), hypertext term (1965), Web (1989 to 1991).</li><li>SGML = markup with a DTD. ODA = logical + layout structure. MHEG = multimedia objects for exchange.</li></ul></div>
<div class="cheat-terms"><b>Key terms</b><dl><dt>Document</dt><dd>Structured collection of information, shown to a reader.</dd><dt>Logical structure</dt><dd>Organisation into chapters, sections, paragraphs.</dd><dt>Layout structure</dt><dd>How content is placed on the page or screen.</dd><dt>Content</dt><dd>The actual text, images, audio.</dd><dt>Document architecture</dt><dd>Model describing how a document is built.</dd><dt>Node</dt><dd>A unit of information.</dd><dt>Link</dt><dd>A connection between nodes or anchors.</dd><dt>Anchor</dt><dd>The active spot inside a node where a link starts or ends.</dd><dt>Hypermedia</dt><dd>Hypertext with audio, video and images.</dd><dt>Dexter model</dt><dd>Reference model for hypertext systems.</dd><dt>Memex</dt><dd>Vannevar Bush&#x27;s 1945 idea of a linked personal information machine.</dd><dt>Hypertext</dt><dd>Term coined by Ted Nelson in 1965.</dd><dt>World Wide Web</dt><dd>Proposed by Tim Berners-Lee in 1989; first web site in 1991.</dd><dt>Browser</dt><dd>Program that displays and follows links.</dd><dt>Authoring system</dt><dd>Tool used to create hypermedia.</dd><dt>SGML</dt><dd>Standard Generalized Markup Language, ISO 8879.</dd></dl></div>

<section class="cheat"><h2>Unit 10: Synchronization</h2>
<div class="cheat-f"><b>Formulas and facts</b><ul><li>Lip sync: skew within ±80 ms</li><li>Drift = clock error × time (0.1% × 600 s = 0.6 s)</li><li>Fix: clock sync, buffering, adaptive playout</li></ul></div>
<div class="cheat-hooks"><b>Memory hooks</b><ul><li>Intra = smooth within a stream. Inter = aligned between streams. Live = real time source, synthetic = pre-planned.</li><li>Four layers: media, stream, object, specification.</li><li>Lip sync tolerance: audio may be 80 ms behind to 80 ms ahead of the video.</li><li>Four common categories: interval-based, axes (timeline) based, control-flow based, event-based.</li><li>Delay variation is removed by buffers; clock drift by clock sync.</li></ul></div>
<div class="cheat-terms"><b>Key terms</b><dl><dt>Intra-object sync</dt><dd>Correct timing inside one medium.</dd><dt>Inter-object sync</dt><dd>Correct timing between different media.</dd><dt>Live synchronization</dt><dd>Sync of live, captured media.</dd><dt>Synthetic synchronization</dt><dd>Planned timing of stored media.</dd><dt>Hard / soft sync</dt><dd>Strict / tolerant timing relation.</dd><dt>Skew</dt><dd>Time difference between streams.</dd><dt>Media layer</dt><dd>Single continuous stream of LDUs.</dd><dt>Stream layer</dt><dd>Groups of streams and their sync.</dd><dt>Object layer</dt><dd>Complete multimedia objects, including discrete media.</dd><dt>Specification layer</dt><dd>Author&#x27;s description of the presentation.</dd><dt>Reference model</dt><dd>Structured view that guides system design.</dd><dt>Lip synchronization</dt><dd>Matching speech to lip movement.</dd><dt>Tolerance</dt><dd>The error people still accept.</dd><dt>Jitter</dt><dd>Short-term delay variation.</dd><dt>Presentation requirement</dt><dd>Timing limit that quality depends on.</dd><dt>Specification</dt><dd>Formal description of timing relations.</dd></dl></div>

<section class="cheat"><h2>Unit 11: Abstraction of Programming</h2>

<div class="cheat-hooks"><b>Memory hooks</b><ul><li>Low to high: device, library, system software, toolkit, higher language, object-oriented.</li><li>Simple objects (BMO), simple multimedia objects (SMO) and compound multimedia objects (CMO).</li><li>Two models: data as time capsules, data as streams.</li><li>Toolkit = ready-made parts. <section class="cheat"><h2>Unit 12: Multimedia Application</h2>
<div class="cheat-f"><b>Formulas and facts</b><ul><li>Development cycle: plan → design (storyboard) → produce → test → deliver</li><li>Systems: input + processing + storage + output components</li><li>Applications: VoD, video conferencing, education, information systems, digital libraries, entertainment</li></ul></div>
<div class="cheat-hooks"><b>Memory hooks</b><ul><li>VoD needs a server, a network and a set-top box. Conferencing needs low delay.</li><li>Six classes: games, repositories, iTV/VoD, conferencing/mail, shared workspaces, business workflow.</li><li>Plan → Design → Produce → Test → Deliver, and always check copyright.</li><li>Three component groups: input, output, storage.</li></ul></div>
<div class="cheat-terms"><b>Key terms</b><dl><dt>Video on demand</dt><dd>Watch a chosen video when you want.</dd><dt>Video conferencing</dt><dd>Live audio-video link between sites.</dd><dt>Set-top box</dt><dd>Connects the TV to the digital network.</dd><dt>Computer-based training</dt><dd>Learning delivered by computer.</dd><dt>Information system</dt><dd>System for storing and retrieving information.</dd><dt>Game systems</dt><dd>Leaders in multimedia technology.</dd><dt>Repository</dt><dd>Large indexed database, mostly play-back.</dd><dt>Interactive TV</dt><dd>TV with interactive services.</dd><dt>Shared workspace</dt><dd>Remote users see the same application.</dd><dt>Workflow</dt><dd>Business process using multimedia data.</dd><dt>Storyboard</dt><dd>Sequence of sketches showing the screens and flow.</dd><dt>Prototype</dt><dd>Early working version.</dd><dt>Rights and permissions</dt><dd>Legal permission to use others&#x27; content.</dd><dt>Testing</dt><dd>Finding and fixing problems.</dd><dt>Delivery</dt><dd>Publishing the product to users.</dd><dt>Input systems</dt><dd>Devices that capture media: camera, microphone, scanner.</dd></dl></div>
